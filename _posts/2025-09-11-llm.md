这篇笔记围绕三个问题整理：LoRA 究竟学习哪个矩阵，参数减少体现在哪里，以及 QLoRA 的“4-bit”指什么。先把一个线性层算清楚，再考虑如何接入大模型。

文中的小例子用于检查计算过程；最后的实验表留待实际微调时填写，不代表已经完成了大模型实验。

## 1. LoRA 学习的是权重更新量

全量微调直接更新预训练权重。LoRA（Low-Rank Adaptation）冻结原权重 $$W_0$$，另外学习两个小矩阵 $$A$$、$$B$$，用它们的乘积表示更新量：

$$
W = W_0 + \Delta W,\qquad \Delta W = sBA,\qquad s = \frac{\alpha}{r}.
$$

这里采用标准 LoRA 的缩放方式。低秩约束加在 $$\Delta W$$ 上，不要求 $$W_0$$ 本身低秩，也不是先对原权重做一次分解，再用小矩阵替换它。[LoRA 原论文](https://arxiv.org/abs/2106.09685)

我理解这一点时最有用的区分是：**原来的知识仍由完整的基座权重承载，小矩阵提供当前任务需要的调整。** 至于低秩调整是否足够，需要由具体任务的验证结果判断。

## 2. 先统一矩阵形状

以下与 PyTorch 的 `nn.Linear(in_features, out_features)` 权重排列一致，暂时省略偏置。

| 对象 | 形状 | 含义 |
| --- | --- | --- |
| $$W_0$$ | $$[d_{out}, d_{in}]$$ | 冻结的原权重 |
| $$A$$ | $$[r, d_{in}]$$ | 将输入映射到低维空间 |
| $$B$$ | $$[d_{out}, r]$$ | 将低维表示映射到输出空间 |
| $$BA$$ | $$[d_{out}, d_{in}]$$ | 与原权重同形状的更新方向 |
| $$X$$ | $$[n, d_{in}]$$ | 一批输入，样本按行排列 |

单个列向量输入 $$x$$ 的前向计算为：

$$
y = W_0x + sB(Ax).
$$

换成按行排列的批量输入，则是：

$$
Y = XW_0^\top + s(XA^\top)B^\top.
$$

检查维度时，可以把额外分支写成：`[n, d_in] → [n, r] → [n, d_out]`。两条分支的输出形状一致，才能相加。

因为 $$\operatorname{rank}(BA) \leq r$$，这里的 $$r$$ 是更新矩阵秩的上限，不保证训练后恰好达到这个秩。

## 3. 参数量到底减少了多少

对于一个没有偏置的线性层，全量微调需要更新的参数量是：

$$
N_{full} = d_{out}d_{in}.
$$

仅训练 LoRA 分支时，可训练参数量是：

$$
N_{LoRA} = rd_{in} + d_{out}r = r(d_{in}+d_{out}).
$$

沿用原笔记中的例子：$$W_0 \in \mathbb{R}^{1024\times512}$$，取 $$r=32$$。

| 项目 | 计算 | 参数量 |
| --- | --- | ---: |
| 原权重 | $$1024\times512$$ | 524,288 |
| $$A$$ | $$32\times512$$ | 16,384 |
| $$B$$ | $$1024\times32$$ | 32,768 |
| LoRA 分支合计 | $$16,384+32,768$$ | 49,152 |

$$
\frac{N_{LoRA}}{N_{full}} = \frac{49,152}{524,288} = 9.375\%.
$$

准确表述应当是“这个线性层的可训练参数量为全量微调的 9.375%”。这个比例不能解释为“保留了原始特征分布的 9%”，也不能直接当作整个模型的显存比例。

训练时仍要加载基座权重；未合并时，这个层实际保存的是 $$W_0$$、$$A$$、$$B$$。主要节省来自不再为基座参数保存梯度和优化器状态，激活值等开销仍然存在。

## 4. 分清 r、alpha 和学习率

| 设置 | 直接控制什么 | 阅读配置时的提醒 |
| --- | --- | --- |
| `r` | 小矩阵尺寸与更新的秩上限 | 增大后参数更多，但效果不保证单调提升 |
| `lora_alpha` | 分支缩放系数的分子 | 要结合 `r` 和采用的缩放规则理解 |
| `learning_rate` | 优化器每步如何更新参数 | 是独立超参数，不能用 `alpha/r` 替代 |

对固定的 $$A$$、$$B$$，增大 $$s$$ 会放大分支输出。但训练过程中，缩放还会改变梯度，参数也会随之变化，因此不能由较大的 $$\alpha/r$$ 直接推出更好的适配效果。

例如，`r=8, alpha=16` 与 `r=16, alpha=32` 都有 $$s=2$$，两者的参数量和可表示的更新仍不同。保持缩放相同，并不等于控制了所有实验变量。

这篇笔记只讨论标准 LoRA；实现中的其他变体可能采用不同缩放规则，读配置时应确认这一点。[PEFT LoRA 文档](https://huggingface.co/docs/peft/developer_guides/lora)

## 5. 初始化、训练和合并

### 为什么常见初始化是 A 随机、B 为零

在这种初始化下，$$BA=0$$，所以接入 LoRA 后的初始输出与基座一致。PEFT 默认对 $$A$$ 使用 Kaiming-uniform 初始化，对 $$B$$ 使用零初始化；下面的教学例子改用小尺度正态分布初始化 $$A$$。[PEFT 初始化说明](https://huggingface.co/docs/peft/developer_guides/lora#initialization)

设 $$G=\partial L/\partial(\Delta W)$$，由链式法则得到：

$$
\frac{\partial L}{\partial A}=sB^\top G,\qquad
\frac{\partial L}{\partial B}=sGA^\top.
$$

因此，第一次反向传播时，$$A$$ 来自任务损失的梯度为零，$$B$$ 的梯度通常非零；更新 $$B$$ 后，后续步骤才可能让 $$A$$ 获得非零梯度。若把两个矩阵都初始化为零，两者的任务梯度都会为零。

这里说的是损失梯度；带权重衰减的优化器还可能通过衰减项改变参数，不能把“梯度为零”和“参数绝对不变”混为一谈。

### 冻结权重不等于关闭整个计算图

基座参数设置 `requires_grad=False`，优化器只接收适配器参数。多层模型中，梯度仍可能需要经过冻结层，才能到达更早的 LoRA 分支，因此不能把整个基座前向直接包进 `torch.no_grad()`。

### 推理时为什么可以合并

对本文这种没有额外非线性的 LoRA 分支，可以预先计算：

$$
W_{merged}=W_0+sBA.
$$

此时一次普通线性运算就能得到相同结果。若使用 LoRA dropout，应在推理模式、dropout 关闭后比较；浮点计算允许有舍入误差。合并后应移除或禁用额外分支，避免重复加上更新。

单独保存适配器便于切换任务，但加载时还需要匹配的基座模型及配置。量化模型的合并可能涉及反量化与重新量化，应另外核对实现和合并前后的输出。

## 6. 用一个小例子检查计算过程

下面只依赖 PyTorch，在 CPU 上使用 `4 → 3` 的线性层和 `r=2` 的适配器。基座是随机生成的教学对象，不代表预训练模型；合成目标也不用于评价微调效果。

```python
import torch
from torch import nn
from torch.nn import functional as F

torch.manual_seed(7)


class LoRALinear(nn.Module):
    def __init__(self, base, rank=2, alpha=4):
        super().__init__()
        self.base = base
        self.base.requires_grad_(False)
        self.scale = alpha / rank
        self.A = nn.Parameter(torch.empty(rank, base.in_features))
        self.B = nn.Parameter(torch.zeros(base.out_features, rank))
        nn.init.normal_(self.A, mean=0.0, std=0.02)

    def forward(self, x):
        update = F.linear(F.linear(x, self.A), self.B)
        return self.base(x) + self.scale * update

    def merged_weight(self):
        return self.base.weight + self.scale * (self.B @ self.A)


base = nn.Linear(4, 3, bias=False)
layer = LoRALinear(base)
x = torch.randn(6, 4)
w_before = base.weight.detach().clone()
with torch.no_grad():
    target = F.linear(x, w_before + 0.1 * torch.randn(3, 4))
    torch.testing.assert_close(layer(x), base(x))

trainable = [p for p in layer.parameters() if p.requires_grad]
assert sum(p.numel() for p in trainable) == 2 * (4 + 3)
optimizer = torch.optim.Adam(trainable, lr=0.03)

for step in range(100):
    optimizer.zero_grad(set_to_none=True)
    loss = F.mse_loss(layer(x), target)
    loss.backward()
    if step == 0:
        initial_loss = loss.item()
        assert layer.A.grad is not None
        assert torch.count_nonzero(layer.A.grad).item() == 0
        assert layer.B.grad is not None
        assert layer.B.grad.norm().item() > 0
    assert base.weight.grad is None
    optimizer.step()

layer.eval()
with torch.no_grad():
    separate = layer(x)
    merged = F.linear(x, layer.merged_weight())
    torch.testing.assert_close(separate, merged, rtol=1e-5, atol=1e-6)
    assert torch.equal(base.weight, w_before)
    final_loss = F.mse_loss(separate, target).item()

print("trainable parameters:", sum(p.numel() for p in trainable))
print(f"loss: {initial_loss:.6f} -> {final_loss:.6f}")
print("initialization, gradients, frozen base, and merge checks passed")
```

这个例子检查了初始输出不变、第一步梯度、基座冻结和合并前后输出一致。可训练参数应为 `14`；这组小尺寸下原权重只有 `12` 个参数，反而更少——LoRA 只有在 $$r(d_{in}+d_{out})<d_{in}d_{out}$$ 时才节省该层的可训练参数。

可以再把两个初始化都改为零，观察梯度检查为什么失败；这是理解初始化作用的一个自测，而不是建议的训练设置。

## 7. QLoRA：把存储精度与计算精度分开看

普通 LoRA 冻结基座，却仍需保存基座权重。QLoRA 进一步将基座权重量化存储，并让梯度通过冻结的量化基座传到 LoRA 分支，训练的仍是适配器。[QLoRA 原论文](https://arxiv.org/abs/2305.14314)

用 $$\hat W_0$$ 表示量化权重反量化后参与运算的值，可以近似写成：

$$
y=\hat W_0x+sB(Ax).
$$

$$\hat W_0$$ 一般不与原始高精度 $$W_0$$ 完全相等；量化有误差，实际计算也需要处理量化尺度等元数据。

| 论文中的机制 | 主要解决什么 |
| --- | --- |
| NF4（4-bit NormalFloat） | 使用适合近似正态分布权重的非均匀量化表示 |
| Double quantization | 进一步量化量化常数，减少元数据开销 |
| Paged optimizers | 借助统一内存管理优化器状态，缓解显存峰值 |

这三者作用不同。分页优化器并不会消除优化器状态，也不应当把它与“所有参数都用 4-bit 训练”画等号。[QLoRA 方法说明](https://arxiv.org/html/2305.14314v1)

在常见配置中，基座权重以 4-bit 形式存储，计算使用 BF16 或 FP16 等更高精度；适配器、梯度、优化器状态和激活值也有各自的数据类型。`bnb_4bit_compute_dtype` 控制计算类型，不能仅凭 `load_in_4bit=True` 推断全部运算精度。[Transformers bitsandbytes 文档](https://huggingface.co/docs/transformers/quantization/bitsandbytes#compute-data-type)

所以，“4-bit”不能直接换算成整次训练的总显存。QLoRA 首先解决的是显存压力；反量化开销、硬件、算子实现及输入尺寸都会影响耗时，是否更快需要在同样的实验条件下测量。

## 8. 接到真实模型前，我会先检查什么

使用 PEFT 时，可以把前面的概念对应到下面几项配置。这里记录含义，不给出未经验证的整套训练脚本。

| 配置或检查 | 需要确认的内容 |
| --- | --- |
| `target_modules` | 实际模块名称是否匹配模型；不要默认所有模型都叫 `q_proj`、`v_proj` |
| `r`、`lora_alpha` | 记录两者以及缩放规则，避免只比较 `r` |
| `lora_dropout` | 训练时的正则化设置；评估时应进入 `eval()` 模式 |
| `bias`、`modules_to_save` | 是否有适配器之外的参数一起训练和保存 |
| 可训练参数统计 | 接入后打印名称和数量，确认基座没有意外解冻 |
| QLoRA 配置 | 记录量化类型、double quant、计算类型和优化器 |

针对量化训练，还应按所用版本的官方流程准备模型，例如 PEFT 的 `prepare_model_for_kbit_training`，再接入适配器。训练前核对已安装版本的文档，并记录依赖版本，便于复现。[PEFT 量化训练指南](https://huggingface.co/docs/peft/developer_guides/quantization)

复习时，我会用这四个问题检查自己是否真的理解：

1. 当输入是 `[batch, d_in]` 时，为什么代码中的更新是 `X @ A.T @ B.T`？
2. `B=0` 时，为什么初始输出不变，但训练仍然能够开始？
3. 单层可训练参数减少到 9.375%，为什么不能据此推断总显存？
4. QLoRA 的基座权重以 4-bit 存储，为什么计算精度仍要单独配置？
