> 这篇笔记整理学习 LLM 时容易混淆的几个基础问题：文本如何变成 token，注意力为什么要缩放，RoPE 如何引入相对位置，以及 SwiGLU 到底改变了什么。复习时先看概念与形状，再运行小实验，最后对照易错点检查理解。

## 1. 先把几个模块放回模型里

下面是一条简化的、采用 RoPE 和 SwiGLU 的 decoder-only 模型计算路径：

```text
文本
  → Tokenizer：得到 token IDs
  → Embedding：查表得到向量
  → 多层 Transformer block
      → 归一化与 Q/K/V 投影
      → 对 Q、K 应用 RoPE
      → 带因果掩码的注意力、输出投影与残差
      → 归一化、SwiGLU 前馈层与残差
  → 最终归一化与 LM Head
  → 下一个 token 的 logits
```

这里只用它定位知识点；不同模型的归一化、残差和位置编码设计可能不同。**Tokenizer 处理文本表示，RoPE 处理位置，Attention 混合不同位置的信息，FFN 变换每个位置的特征。**

全文使用以下记号：

| 记号 | 含义 |
| --- | --- |
| $B$ | batch size |
| $T$ | 当前输入的序列长度 |
| $V$ | 词表大小 |
| $d_{\text{model}}$ | 模型隐藏维度 |
| $H$、$d_h$ | 注意力头数与每个头的维度；本文标准多头示例中 $d_{\text{model}}=H d_h$ |
| $m$ | FFN 的中间维度 |

## 2. Tokenizer：先分清“长度”在量什么

### 2.1 Token、ID 与 Embedding 是三件事

Tokenizer 把文本映射为离散的 token IDs；Embedding 再按照 ID 查出可训练向量。ID 是索引，不是语义坐标：编号相邻的两个 token，不代表意思相近。

```text
文本 → token IDs: [B, T]
     → embedding: [B, T, d_model]
```

一个 token 可以对应单词、子词、标点、空格或部分字节。中文字符数与 token 数没有固定比例，应使用目标模型的 tokenizer 实测。

### 2.2 四种常见“长度”

| 想问的问题 | 应查看的对象 | 容易混淆的地方 |
| --- | --- | --- |
| 这段文本有多少 token？ | 单条输入的 `len(input_ids)` | 设置 `return_tensors="pt"` 后应看 `shape[-1]`，`len(tensor)` 通常是 batch 大小 |
| tokenizer 一共能编码多少个 token？ | `len(tokenizer)` | 在 Hugging Face 常用实现中包含后续添加的 token |
| 原始词表多大？ | `tokenizer.vocab_size` | 通常不包含后来添加的 token；要结合具体实现看 |
| 模型一次能处理多长的序列？ | 模型配置、模型说明与运行时限制 | `tokenizer.model_max_length` 只是配置值，未配置时可能是极大的占位整数 |

这些 API 的含义可对照 [Hugging Face Tokenizer 文档](https://huggingface.co/docs/transformers/main_classes/tokenizer)。

对常见 decoder-only 生成流程，可以先用下面的预算关系检查输入：

$$
T_{\text{prompt}} + T_{\text{new}} \le T_{\text{context}}
$$

其中 prompt 包含实际送入模型的全部模板和特殊 token。超长输入如何处理，取决于调用端是否截断、服务端是否拒绝，以及模型是否使用滑动窗口等机制，不能一概描述成“模型自动忘掉最早内容”。`model_max_length` 改大也不会自动扩展模型能力。

### 2.3 子词算法不是词根分析器

BPE 的基本思路是反复合并语料中高频的相邻符号；byte-level BPE 从字节表示出发。合并结果可能看起来像词根，但算法并没有保证语言学意义上的词根边界。

WordPiece、Unigram 是其他常见方案。SentencePiece 是可以支持 BPE、Unigram 等方法的工具，不宜直接等同于某一种算法。简要对照见 [Tokenization algorithms](https://huggingface.co/docs/transformers/tokenizer_summary)。

学习时记住两点就够了：

- 一个词如何切分，取决于具体 tokenizer 的词表、规则和预处理，不能凭词义猜测 token IDs。
- 编码后能否逐字还原，要看归一化、未知字符处理、特殊 token 和解码选项；“所有 tokenizer 都完全无损”并不成立。

### 2.4 小实验：观察真实切分结果

下面只加载 GPT-2 的 tokenizer，不下载模型权重。运行需要安装 `transformers`，首次加载需要访问 Hugging Face。选 GPT-2 是为了观察 byte-level BPE，不代表推荐用它做中文任务。

```python
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("openai-community/gpt2")

for text in ["Robot control is a sequence problem.", "机器人需要视觉反馈。"]:
    ids = tokenizer.encode(text, add_special_tokens=False)
    restored = tokenizer.decode(
        ids,
        skip_special_tokens=False,
        clean_up_tokenization_spaces=False,
    )

    print("text:", text)
    print("tokens:", tokenizer.convert_ids_to_tokens(ids))
    print("ids:", ids)
    print("sequence length:", len(ids))
    print("round trip:", restored == text)
    assert restored == text

print("base vocabulary:", tokenizer.vocab_size)
print("with added tokens:", len(tokenizer))
print("configured maximum:", tokenizer.model_max_length)
```

不预填 token IDs：直接以实际运行结果为准。在 GPT-2 的 token 字符串中，`Ġ` 是空格的可视表示之一；部分中文 token 单独显示不易读，也不等于整个序列无法解码。

进一步可以比较 `"robot"` 与 `" robot"`，观察前导空格是否改变切分。需要批量输入时，再区分 padding 和 truncation：前者补齐长度，后者丢弃超限内容，具体行为见 [padding/truncation 文档](https://huggingface.co/docs/transformers/main/en/pad_truncation)。

## 3. 词表大小：参数量与序列长度的取舍

忽略偏置时，Embedding 参数量为：

$$
P_{\text{embed}}=Vd_{\text{model}}
$$

如果 LM Head 与 Embedding 不共享权重，输出投影还需要约 $Vd_{\text{model}}$ 个参数；如果共享，则不能把同一组参数重复计算。

以 $d_{\text{model}}=4096$ 为例，词表从 30,000 扩到 250,000，单个 Embedding 矩阵增加：

$$
(250000-30000)\times4096=901120000
$$

即约 9.01 亿个参数。这只是参数算术，不说明模型效果一定更好或更差。

| 影响 | 应如何理解 |
| --- | --- |
| 编码长度 | 更丰富的词表可能减少某些语言的 token 数，但依赖训练语料与分词规则 |
| 参数与输出计算 | 词表越大，Embedding 和词表投影通常越大 |
| 训练覆盖 | 低频 token 的表示可能缺少足够样本支持 |
| 端到端速度 | 要同时看编码后的长度、prefill、逐 token 解码和输出层成本 |

因此，“大词表一定推理更快”与“小词表一定多语言能力差”都过于绝对。实际比较应固定文本、模型规模、硬件与生成条件，记录 token 数、延迟和效果。

## 4. 注意力为什么除以 $\sqrt{d_h}$？

### 4.1 缩放控制的是点积的统计尺度

单个注意力头的计算为：

$$
\operatorname{Attention}(Q,K,V)
=
\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_h}}+M\right)V
$$

这里 $M$ 是加性掩码：允许的位置为 $0$，禁止的位置为 $-\infty$。softmax 沿 key 位置所在的最后一维计算。

假设 $q_i$、$k_i$ 均值为 0、方差为 1，且各分量满足独立性条件，则：

$$
\mathbb{E}\left[\sum_{i=1}^{d_h}q_i k_i\right]=0,
\qquad
\operatorname{Var}\left(\sum_{i=1}^{d_h}q_i k_i\right)=d_h
$$

所以除以 $\sqrt{d_h}$ 后，方差变为 1。这个推导来自 [Attention Is All You Need 的缩放点积注意力](https://arxiv.org/abs/1706.03762)，用于解释尺度选择；训练中的实际 Q/K 不必严格服从这些假设。

**方差为 1 不等于严格服从标准正态分布，也不意味着数值被限制在某个固定区间内。**

### 4.2 softmax 关注的是差值，不是绝对大小

$$
\operatorname{softmax}(z+c\mathbf{1})
=
\operatorname{softmax}(z)
$$

整体平移 logits 不改变概率；扩大 logits 之间的差距才会使分布更尖锐。其导数满足：

$$
\frac{\partial p_i}{\partial z_j}
=
p_i(\delta_{ij}-p_j)
$$

当分布接近 one-hot 时，很多导数会很小。缩放有助于控制这种现象，但不能据此断言“不缩放就完全不能训练”。

### 4.3 小实验：缩放、掩码与形状

以下 PyTorch 示例可在 CPU 上独立运行。让每个位置都至少能关注自己，可避免一整行被掩码为 $-\infty$ 后出现无效 softmax。

```python
import math
import torch

torch.manual_seed(7)
batch, heads, length, head_dim = 2, 4, 6, 8
q = torch.randn(batch, heads, length, head_dim, dtype=torch.float64)
k = torch.randn_like(q)
v = torch.randn_like(q)

raw_scores = q @ k.transpose(-2, -1)  # [B, H, T, T]
scaled_scores = raw_scores / math.sqrt(head_dim)

# True 表示禁止关注：上三角对应未来位置。
blocked = torch.ones(length, length, dtype=torch.bool).triu(diagonal=1)
scores = scaled_scores.masked_fill(blocked, float("-inf"))
weights = torch.softmax(scores, dim=-1)
out = weights @ v  # [B, H, T, d_h]

assert out.shape == q.shape
assert torch.isfinite(out).all()
assert torch.count_nonzero(weights[..., blocked]).item() == 0
torch.testing.assert_close(
    weights.sum(dim=-1), torch.ones_like(weights[..., 0])
)

# 用未掩码分数验证 softmax 的平移不变性。
torch.testing.assert_close(
    torch.softmax(scaled_scores, dim=-1),
    torch.softmax(scaled_scores + 100.0, dim=-1),
)
print("output shape:", tuple(out.shape))
print("causal mask and softmax checks passed")
```

阅读其他实现时，不要凭变量名猜布尔掩码的含义：有的 API 用 `True` 表示允许，有的表示禁止。这个实验只定义了上面 `blocked` 的约定。

## 5. RoPE：用旋转把位置写进 Q 和 K

### 5.1 相对位置从哪里来？

设 $R_m$ 是位置 $m$ 对应的旋转矩阵，对 Q/K 做：

$$
\widetilde q_m=R_mq_m,\qquad \widetilde k_n=R_nk_n
$$

则它们的点积为：

$$
\widetilde q_m^\top \widetilde k_n
=
q_m^\top R_m^\top R_n k_n
=
q_m^\top R_{n-m}k_n
$$

位置部分以相对距离 $n-m$ 进入计算。这不代表“距离相同，注意力分数就相同”：分数仍然依赖内容向量 $q_m$ 与 $k_n$。固定内容向量，同时平移两个位置，才是这里要验证的性质。推导见 [RoFormer 论文](https://arxiv.org/abs/2104.09864)。

在常见 decoder 实现中，RoPE 作用于投影后的 Q、K 的每头维度，通常不作用于 V；不要直接把模型的总隐藏维度当作旋转维度。计算出更长位置的正余弦值，也不自动保证模型具备可靠的长上下文能力。

### 5.2 最容易混淆的两种维度配对

以 $d_h=8$ 为例：

| 布局 | 配对方式 | 每维对应的角频率 |
| --- | --- | --- |
| 相邻配对 | $(0,1),(2,3),(4,5),(6,7)$ | $[\theta_0,\theta_0,\theta_1,\theta_1,\ldots]$ |
| 前后半配对 | $(0,4),(1,5),(2,6),(3,7)$ | $[\theta_0,\theta_1,\theta_2,\theta_3,\theta_0,\ldots]$ |

这篇笔记采用前后半配对：

```text
x = [a0, a1, a2, a3, b0, b1, b2, b3]
rotate_half(x) = [-b0, -b1, -b2, -b3, a0, a1, a2, a3]
```

因此，频率必须用 `cat([angles, angles])` 复制两半；如果采用相邻配对，才需要对应的交错重复布局。两种约定可以通过一致的维度置换关联，但加载已有权重时不能只换旋转函数而忽略 Q/K 投影的排列。

原笔记把“前后半配对的代码”解释成“相邻配对的频率”，这是需要特别纠正的地方。

### 5.3 小实验：逐向量保范数与位置平移

以下代码约定输入为 `[B, H, T, d_h]`、位置索引为 `[T]`，整个 batch 共用位置序列。它是基础 RoPE 的教学实现，不含模型专用的长上下文缩放。

```python
import torch

def rope_split_half(x, positions, base=10000.0):
    if x.ndim != 4 or x.shape[-1] % 2:
        raise ValueError("x must have shape [B, H, T, even head_dim]")
    if positions.ndim != 1 or positions.numel() != x.shape[-2]:
        raise ValueError("positions must have shape [T]")
    if not x.is_floating_point() or base <= 0:
        raise ValueError("use floating-point x and a positive base")

    head_dim = x.shape[-1]
    inv_freq = base ** (
        -torch.arange(0, head_dim, 2, device=x.device, dtype=torch.float32)
        / head_dim
    )
    angles = positions.to(device=x.device, dtype=torch.float32)[:, None] * inv_freq
    angles = torch.cat([angles, angles], dim=-1)[None, None, :, :]

    # 为了看清计算过程，先在 float32 中旋转，再还原输入 dtype。
    xf = x.float()
    left, right = xf.chunk(2, dim=-1)
    rotated = torch.cat([-right, left], dim=-1)
    return (xf * angles.cos() + rotated * angles.sin()).to(x.dtype)

torch.manual_seed(7)
q = torch.randn(2, 3, 5, 8)
k = torch.randn_like(q)
positions = torch.arange(5)
qr = rope_split_half(q, positions)
kr = rope_split_half(k, positions)

# 1. 每个位置、每个 head 的范数保持不变。
torch.testing.assert_close(qr.norm(dim=-1), q.norm(dim=-1), atol=1e-5, rtol=1e-5)

# 2. 内容不变，同时平移 Q/K 的位置，点积矩阵保持不变。
q_shift = rope_split_half(q, positions + 7)
k_shift = rope_split_half(k, positions + 7)
torch.testing.assert_close(
    qr @ kr.transpose(-2, -1),
    q_shift @ k_shift.transpose(-2, -1),
    atol=1e-5, rtol=1e-5,
)

# 3. 分段计算使用真实位置，而不是每段都从 0 开始。
torch.testing.assert_close(
    rope_split_half(q[:, :, 3:, :], positions[3:]),
    qr[:, :, 3:, :],
    atol=1e-5, rtol=1e-5,
)
print("RoPE norm, relative-position and offset checks passed")
```

这些断言比只打印“旋转前后均值不同”更能说明实现是否符合公式。KV cache 解码时还要保证位置偏移正确，已经旋转并缓存的 K 不应重复旋转。

## 6. SwiGLU：带门控的前馈网络

### 6.1 三个投影各做什么？

本文忽略 bias，把一个 SwiGLU FFN 写为：

$$
\operatorname{SwiGLU}(x)
=
W_{\text{down}}
\left[
\operatorname{SiLU}(W_{\text{gate}}x)
\odot
(W_{\text{up}}x)
\right]
$$

其中：

$$
\operatorname{SiLU}(z)=z\,\sigma(z)
$$

gate 与 up 都把特征从 $d_{\text{model}}$ 映射到 $m$，相乘后再由 down 映射回去。$\odot$ 是逐元素乘法，不是向量内积。

**SiLU 的输出不是概率，也不被限制在 $[0,1]$。** “门”表示输入相关的特征调制，不能理解成只会在 0 与 1 之间开关的阀门。

[GLU Variants Improve Transformer](https://arxiv.org/abs/2002.05202) 给出了这类 FFN 变体及实验比较。这里记录结构与参数量，不把实验优势写成“所有任务都更好”或“必然消除梯度问题”。

### 6.2 为什么中间维度常常不是 $4d$？

忽略 bias，普通两投影 FFN 若取中间维度 $4d$，参数量约为：

$$
P_{\text{FFN}}=2d(4d)=8d^2
$$

SwiGLU 有三个投影，因此：

$$
P_{\text{SwiGLU}}=3dm
$$

若想让参数量大致相当，可令 $m\approx\frac{8}{3}d$。实际模型还可能加倍率并按硬件友好的倍数取整，不能把这个推导当作所有模型的配置规则。可以对照 [Meta 的 Llama 参考实现](https://github.com/meta-llama/llama/blob/main/llama/model.py) 阅读。

另外，ReLU、GELU 和 SwiGLU 不能简单按“旧模型/新模型”划分；例如 GPT-2、BERT 使用的是 GELU，并非 ReLU。

### 6.3 小实验：输入输出形状和参数量

使用小尺寸，避免为验证一个公式分配几百 MB 的权重。这里 `hidden_dim` 表示最终中间维度，构造函数不会再偷偷乘一次 $2/3$。

```python
import torch
from torch import nn
from torch.nn import functional as F

class SwiGLU(nn.Module):
    def __init__(self, dim, hidden_dim):
        super().__init__()
        self.gate = nn.Linear(dim, hidden_dim, bias=False)
        self.up = nn.Linear(dim, hidden_dim, bias=False)
        self.down = nn.Linear(hidden_dim, dim, bias=False)

    def forward(self, x):
        return self.down(F.silu(self.gate(x)) * self.up(x))

torch.manual_seed(7)
dim, hidden_dim = 48, 128  # 128 = 8/3 * 48
ffn = SwiGLU(dim, hidden_dim)
x = torch.randn(2, 5, dim, requires_grad=True)
y = ffn(x)

assert y.shape == x.shape
parameter_count = sum(p.numel() for p in ffn.parameters())
assert parameter_count == 3 * dim * hidden_dim == 8 * dim * dim

y.square().mean().backward()
assert x.grad is not None and torch.isfinite(x.grad).all()
assert all(p.grad is not None and torch.isfinite(p.grad).all() for p in ffn.parameters())
print("output shape:", tuple(y.shape))
print("parameters:", parameter_count)  # 18432
```

FFN 对每个位置独立应用同一组权重；它本身不在序列维度上混合 token。门控增加了非线性表达方式，但训练速度仍要通过实际配置与硬件测量。

## 7. 读模型代码时的检查顺序

遇到新模型时，可以用下面的顺序做学习记录：

1. **输入表示**：模型与 tokenizer 是否匹配？特殊 token、聊天模板、padding/truncation 如何设置？
2. **张量形状**：Q/K/V 的 batch、head、sequence、head dimension 分别在哪一维？是否使用不同数量的 query/KV heads？
3. **注意力**：缩放因子用的是每头维度吗？掩码方向、softmax 维度是否正确？
4. **位置编码**：RoPE 是相邻配对还是前后半配对？缓存解码有没有携带正确的位置偏移？
5. **前馈层**：使用什么激活或门控？`intermediate_size` 是最终尺寸还是计算前的基准值？
6. **微调**：哪些投影需要适配、哪些权重冻结？可接着读 [LoRA 与 QLoRA 学习笔记]({% post_url 2025-09-11-llm %})。

研究 VLA 时，也可以沿这条路径检查语言骨干。但视觉特征、机器人状态和动作的表示方式由具体模型决定，不能默认都由文本 tokenizer 编码。
