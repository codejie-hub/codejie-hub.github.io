ViT-VS：Hierarchical Feature Binning 交互式可视化

重点讲清楚 β=1 → 3×3 Average Pooling → 外围 8 个 coarse bins → β=2 拼接 的全过程。
1. DINO feature map
2. β=1 fine bins
3. 3×3 AvgPool
4. pooled map
5. 外围 8 bins
6. 最终 β=2 descriptor
最重要的区分： Average Pooling 作用在 DINO 的 patch feature map 上，而不是 RGB 像素上。 每个格子是一个 D 维 descriptor；平均以后仍然是 D 维。

步骤 1：DINO 先得到 patch feature map

例如输入图像经过 DINOv2-S/14 后，得到一个 patch 网格。为了可视化，下面用 7×7 代替真实的 22×22。 每个格子 F(i,j) 都代表一个 D 维向量。

F(i,j) ∈ R^D 例如 DINOv2-Small: D = 384 所以每个格子不是“一个像素”，而是一个 384 维 descriptor。
当前我们选中心 patch： X = F(3,3)。接下来所有 hierarchical descriptor 都是围绕这个中心 patch 构造的。

步骤 2：β=1 —— 先保留中心 3×3 的 9 个 fine bins

中心 patch X
fine bin（原始 patch descriptor）

β=1 时，不做平均。直接保留中心 patch 和周围 8 个邻居：

fine descriptor = [ F(y-1,x-1), F(y-1,x), F(y-1,x+1), F(y, x-1), F(y, x), F(y, x+1), F(y+1,x-1), F(y+1,x), F(y+1,x+1) ] 共 9 个 D 维向量 → 拼接后维度 = 9D
为什么这里不平均？
因为中心附近的空间结构非常重要：上、下、左、右分别是什么，需要保留下来。

步骤 3：β=2 新增“外层 3×3 Average Pooling”

现在要给中心 patch 增加更远处的上下文。做法不是直接再拿远处单个 patch， 而是先对 整个 feature map 做一个 3×3, stride=1 的滑动平均池化。

当前 3×3 pooling 窗口
这个窗口的 pooled 输出位置
A(i,j) = (1 / N_ij) · ΣΣ F(i+a, j+b) a,b ∈ {-1,0,1} 普通内部位置: N_ij = 9 所以 A(i,j) 仍然 ∈ R^D
非常关键： 这个平均是“逐通道平均”。如果每个 patch descriptor 是 384 维， 那么 9 个 384 维向量平均后，结果仍然是一个 384 维向量。

步骤 4：对整个 feature map 滑动后，得到 pooled feature map A

原始 feature map

F ∈ R^(H' × W' × D)

每个位置描述一个单独 patch 的 DINO feature。

3×3 AvgPool 后

A ∈ R^(H' × W' × D)

每个位置描述“周围 3×3 patch 区域”的平均语义。

F(i,j)：局部单 patch

回答的问题更像：

“这个 patch 自己是什么？”

A(i,j)：3×3 区域摘要

回答的问题更像：

“这个位置附近一小块区域整体是什么？”
这一步是 hierarchical binning 的核心之一：把远处区域从“单 patch 表示”变成“区域摘要表示”。

步骤 5：从 pooled map 中取距离中心 3 个 patch 的 8 个 coarse bins

β=2 不会使用中心位置的 pooled feature，因为中心附近已经由 9 个 fine bins 表达了。 它会在 8 个方向 上，按照 3 patch 的偏移 取 pooled descriptor。

中心 X
中心 3×3 fine
从 A 中采样的 8 个 coarse bins
C1 = A(y-3, x-3) C2 = A(y-3, x) C3 = A(y-3, x+3) C4 = A(y, x+3) C5 = A(y+3, x+3) C6 = A(y+3, x) C7 = A(y+3, x-3) C8 = A(y, x-3)
注意：C4 ≠ F(y,x+3)。
正确的是：C4 = A(y,x+3)，也就是“以 (y,x+3) 为中心的 3×3 patch 区域平均后的 descriptor”。

步骤 6：β=2 的最终 hierarchical descriptor

最终，把两部分拼起来：

9 个 fine bins
中心 3×3 原始 patch features
+
8 个 coarse bins
外围 3×3 AvgPool 区域摘要
→
17 个 bins
最终 descriptor
tilde_f(y,x) = [ fine_1, fine_2, ..., fine_9, C1, C2, ..., C8 ] 总 bin 数 = 9 + 8 = 17 若原始维度 D=384： β=2 descriptor 维度 = 17 × 384 = 6528

β=1 与 β=2 对比

β = 1

中心局部结构

9 个 fine bins

维度：9D

特点：快、局部结构清晰、上下文范围较小。

β = 2

中心细 + 外围粗

9 fine + 8 coarse

维度：17D

特点：上下文更强、匹配更稳，但计算更慢。

一句话总结： β=2 的外层 3×3 Average Pooling，不是为了提高中心点定位精度， 而是为了给中心 patch 增加“远处环境长什么样”的上下文信息，从而减少语义匹配歧义。
